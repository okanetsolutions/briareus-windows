# Sleep mode

Settings → This computer → Sleep after offers Never, 1, 2, 5, 10, 15 or 30 minutes; the default is 5 minutes, saved for this Windows user on this computer. Sleep covers the main window with a dark session wall without replacing navigation, editor contents or drafts. This is an application display mode; it does not lock Windows or suspend the computer.

Up to four working sessions show their title, repository, branch, status, most recently touched file and last command. The existing syntax lexer colors the file as it types, advancing every 80 ms. Project-labelled commands appear below the panes. Recent sessions replay with dimmed text and a Replay label when no session works, or when live activity has been quiet for a minute. New live work takes over. A key, click, physical mouse movement or scroll wakes the app; the waking input and its release are swallowed before native shortcuts or controls receive them.

Unchanged screen-position mouse moves synthesized by Windows when a child appears are ignored; pointer baselines reset on startup, sleep/wake, foreground transitions and modal transitions.

The window waits while a modal dialog is open and resets the idle clock when the dialog ends. Minimizing the main window stops sleep. Detached windows remain separate; input in any window on the app's UI thread wakes the main window. Sleep never deactivates panes or cancels voice, dictation, meetings, SSH or other background work. A modal opened by background activity wakes the wall before it is presented. Attachment file selection and SFTP file/folder pickers participate in the same balanced modal scope, including cancellation.

The wall uses the documented `/events?transcripts=1` stream only while asleep, and the store's asynchronous reads for recent transcripts and `repo_file`. A connect burst can contain all visible sessions, including closed ones: the bounded backlog drops excess session snapshots without disconnecting and schedules `/sessions` reconciliation, while preserving FIFO transcript and deletion events. Connect snapshots and the 128-record table prefer active and recent sessions, protect displayed records and use least-recent victims within equal priorities. Transcript traffic does not invalidate a pending session snapshot; session/deletion changes still reject an older response. All full-list read triggers share a 30-second minimum interval, and stale/failed responses back off to 60 seconds. Up to four unresolved live packets wait for a valid snapshot and can take over a pane after resolution. Genuine stream failures use increasing 2/4/8/16/32/60-second backoff (respecting Retry-After), reset after a healthy minute or a wake/scope reset, then reconcile sessions and catch up displayed transcripts. File reads try the session branch first, then the default branch on a 404. These are **last pushed branch contents**, not live or unsaved workspace edits; new or unpushed files may be unavailable. Read/stream failures remain quiet, with an empty wall or File unavailable. The display retains at most four file contents, 160 lines and 32 KiB per file, 40 normalized replay steps per pane, 30 ticker entries and 128 session records/queued stream events, plus at most 128 lightweight identity/sequence watermarks for evicted records. It clears all display/history state when waking or changing credentials, endpoint or device project scope.

## Verification and portability

Deterministic core tests cover idle deadlines, wake gesture suppression, settings values, path/tool parsing, selection, assignments, replay and ticker bounds, file dwell, branch arguments and stale file revisions. App tests substitute a clock and stream and use fake HTTP transport to exercise native queued input suppression (including stationary and changed screen points), draft preservation, picker cancellation, modal lifecycle, cancellation and credential scope changes. A fake stream runs the real worker adapter through 220 distinct connect records and subsequent live events; controller tests verify bounded reconciliation, fifth-session pane rotation under a newest-first 220-record archive, prolonged unknown transcripts and metadata churn, and stale deletion/sequence protection. Windows CI remains authoritative for MSVC, sanitizer, leak and native execution results.

The Switch port builds core/app unchanged. The new portable core logic needs no shim. The native controller uses the existing window/timer primitives plus `SetWindowsHookExW(WH_GETMESSAGE)`, `CallNextHookEx` and `UnhookWindowsHookEx`; the Switch shim must expose these and filter input before dispatch, or replace `app/sleep_mode.c` with a platform input/controller implementation. A no-op hook must return NULL so automatic sleep stays disabled rather than allowing clickthrough. No OS lock, suspend or global input hook is introduced.

# Mail inbox

Global **Mail** is the envelope icon in the sidebar. It opens the synced inbox for Admin tokens when the server catalog advertises both `GET /settings/mail/accounts` and `GET /mail/messages`. A settings-only server keeps account setup under Settings → Mail. Selecting messages additionally requires `GET /mail/accounts/{account}/messages/{id}`. Connecting a mailbox, its label, sync window and disconnect live under Settings → Mail, not on the inbox.

All mailboxes or one connected account can be read newest first in pages of 50. The mailbox menu chooses the account. Search, an exact label and an exact thread ID stay text filters. **Unread only** and **Starred** send that flag as true, and a second click clears it. **Folder** offers Any, Inbox, Outside inbox, or an exact label. Any, Inbox, and Outside clear a label; applying an exact label clears the inbox choice, so the request never sends both. **People**, **Notifications** and **All**, and grouping by account plus thread id, filter the loaded page on the client and do not refetch. The grouping menu checks that live group even while an exact thread id is set. A notification is a message whose labels include `CATEGORY_PROMOTIONS`, `CATEGORY_UPDATES`, `CATEGORY_SOCIAL` or `CATEGORY_FORUMS`, or whose sender contains `noreply`, `no-reply`, `donotreply`, `notifications@`, `notify@` or `mailer-daemon`. **Reset** clears the server filters and turns grouping back on; the People choice stays until the screen is cleared. Changing a server filter or account cancels outstanding reads, clears the selection and starts from the newest page. Search is limited by the server to 200 characters. Refresh revalidates accounts before rereading the first page. **Load older messages** sends the opaque `nextCursor` unchanged, and the button reads **Load yesterday** only when the oldest loaded message is still from the local today. Rows deduplicate by `(accountId, id)`.

Only selecting a row fetches the full body. The list groups messages that share an account and a thread id, newest first, and the reader shows that thread oldest first. Opening a message scrolls to that message, and stays at the top when it is already the first block. Loading older mail keeps the opened message where that scroll left it, and crossing the stacked width scrolls to it again. A later paint leaves a scroll the reader itself moved. A receivedAt that localtime cannot represent is an undated day. Sender, subject, snippet, relative received date, account, unread and star state describe the synced copy. Bodies render as literal, selectable text, including the server's HTML-to-text fallback; there is no HTML or Markdown renderer, active link or remote-image loading. Raw `body.html` is discarded. Truncation and attachment names, MIME types and byte sizes are shown. **Open at provider**, **Reply at provider** (`r`) and **Delete at provider** (`Delete`) use only a validated HTTPS `webUrl`; the provider's website controls replies, read state and deletion. Delete at provider opens the selected message so you can delete it there, and the synced copy disappears after the next mail sync. The reader has a compact unread-state note and a provider reply button. Narrow panes stack the search below the mailbox selector.

Servers advertising `DELETE /mail/accounts/{account}/messages/{id}` offer **Delete message** (or `Delete`), with confirmation before moving only the selected message to provider trash. The action works without a provider web link, disables repeated clicks while running, removes the message locally on confirmed success, and preserves it with an error on failure. Existing read-only grants return 409 and need reconnecting in Settings → Mail with `gmail.modify` or `Mail.ReadWrite`. Older servers retain **Delete at provider**.

The inbox calls the account-list and two message GET routes, plus the optional message DELETE route. Opening a message here does not mark it read or change its star. Sending/replying, attachment bytes/downloads, other mailbox writes and live-mail events are outside the core contract.

Accounts, filters, rows and the selected body stay in screen memory, with no DiskCache writes. Hiding/destroying the screen, signing out or changing the connection clears private state and cancels request delivery. Account status is reread every 30 seconds while foregrounded; account removal or provider `reauth` clears rows, bodies, cursors and outstanding reads before restarting. Server-side changes become known on this refresh or F5, since the contract has no mail events. Callbacks validate the connection, screen/filter generation, deployed route and selected account+id. Already running transport work may finish after cancellation; its response is discarded without reaching the retired screen.

Deleted/missing-message 404 clears selection and reloads from a validated account snapshot. Filters/cursor failures offer reset/refresh; permission failures clear private content. Network/503/429 failures show safe errors and a bounded exponential cooldown, respecting longer `Retry-After` values. Explicit retry/refresh buttons and periodic account reads obey the cooldown even after leaving/reopening the screen; an account refresh may restart an unloaded first page, while older-page/body failures offer explicit retry.
